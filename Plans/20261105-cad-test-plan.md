## 1. 目的と範囲

- 目的：仕様書の受け入れ条件（AC-01〜AC-31）と、要件プロンプト §9 の最低限のテストを、実装計画書の各段階の完了条件として確認できるようにする。
- 範囲：`Shos.WpfCadSample.Core` の全機能（`Models`、`Controllers`、`ViewModels`、`Serialization`、`Settings`）の自動テスト。WPF アプリ（`Views`、`Infrastructure`）の手動テスト。
- 対象外：UI の自動化テスト（画面操作の記録・再生、スクリーンショットの比較）、性能の自動計測、CI の構築、コードカバレッジの計測ツール。

## 2. テスト方針

### 2.1 レベルと適用範囲

| レベル | 対象 | 方法 | 実行する場所 |
|---|---|---|---|
| 単体テスト | 純粋な型・関数（`Models`、`Serialization` の変換、`Settings` の判定、`Viewport`） | 入力と期待結果。偽の部品は使わない | `Shos.WpfCadSample.Tests`（`dotnet test`） |
| 結合テスト（自動） | `EditorController` と `Drawing` と `Viewport`、`ViewModels` と偽のサービス、ファイル I/O（一時フォルダー）、保存形式の往復 | 複数の実物を組み合わせ、入力の列（`PointerEvent` など）を与えて、状態と通知を検証する | `Shos.WpfCadSample.Tests`（`dotnet test`） |
| 構造テスト（自動） | `Core` の構造（ルート namespace に型がない、WPF への参照がない） | リフレクション | `Shos.WpfCadSample.Tests`（`dotnet test`） |
| 構造の確認（スクリプト） | WPF アプリ側の構造（コードビハインドに `InitializeComponent()` 以外がない、ルート namespace 直下に `App` 以外の型がない） | ソースの検索（付録 A） | 実装計画書 I-10 で実施 |
| 手動テスト（UI） | 画面の表示、マウス・キーボード操作、クリップボードを介した他アプリとの連携、ウィンドウの復元 | 7 章の手順に従って、実際に起動して確認し、結果を記録する | 開発者の Windows デスクトップ |

- UI の自動化テストは行わない（YAGNI）。そのかわり、入力の解釈は `Controllers`、画面の状態は `ViewModels` の自動テストで検証し、`Views` の役割を、入力の変換と表示に限る（設計書 4 章）。

### 2.2 進め方

- テストファースト：実装の前に、失敗するテスト（Red）を書き、最小の実装で成功（Green）させ、整理（Refactor）する。バグの修正は、再現するテストを先に追加する。
- 命名と配置：テストクラスは、対象の型と同じ namespace 構成（`Shos.WpfCadSample.Tests.Models` など）に置き、`<対象>Tests` と名付ける。テストメソッドは、振る舞いが分かる名前にする（例：`Undo_AfterDragCommit_RestoresOriginalShape`）。1 つのテストは 1 つの振る舞いを確認する。
- 決定的であること：時刻・乱数・ファイルシステムの外部状態に依存しない。乱数が必要な場合は、種を固定する。ファイル I/O のテストは、テストごとに作る一時フォルダー（`Tests\Support\TempFolder`）を使い、終了時に削除する。
- 偽の部品：`IDialogService`、`IClipboardService` は、`Tests\Support` に偽の実装（呼び出しの記録と、応答の設定ができるもの）を置く。それ以外は偽にしない。
- 補助：`Tests\Support` に、図形の組み立て補助（`ShapeBuilder`）、ビューの用意（ビューサイズと論理領域から、論理座標 ↔ 画面座標の変換を行う補助）を置く。
- 浮動小数点の比較：許容誤差を明示する（既定 1e-9。スプラインなど反復・連立方程式を含むものは、ケースに記載）。
- テストの独立：テスト間で状態を共有しない。実行順に依存しない。
- 理由のない `Skip` を置かない。保留する場合は、理由と再開の条件を、テストの属性とコメントに明記し、進捗記録に記載する。

### 2.3 テストの実行方法

- 全体（実装計画書の各段階の完了条件。リポジトリルートから）：
  - `dotnet build Source\Shos.WpfCadSample\Shos.WpfCadSample.slnx`
  - `dotnet test Source\Shos.WpfCadSample\Shos.WpfCadSample.slnx`
- 作業中の絞り込み：`dotnet test Source\Shos.WpfCadSample\Shos.WpfCadSample.slnx --filter "FullyQualifiedName~Shos.WpfCadSample.Tests.Models.Geometry"` のように、namespace またはクラス名で絞る。段階の終わりには、必ず全体を実行する。
- 手動テスト：アプリを起動して 7 章の手順を実施し、合否と所見を進捗記録に記録する。

### 付録 B：1,000 図形のファイルの生成（M-20 用。リポジトリには残さない）

```powershell
$random = [System.Random]::new(1)
$shapes = foreach ($i in 1..1000) {
    [ordered]@{
        type = 'line'
        start = [ordered]@{ x = $random.Next(0, 1000); y = $random.Next(0, 700) }
        end = [ordered]@{ x = $random.Next(0, 1000); y = $random.Next(0, 700) }
        attributes = [ordered]@{ color = '#000000'; thickness = 1.0; lineStyle = 'Solid' }
    }
}
[ordered]@{ format = 'Shos.WpfCadSample.Document'; version = 1; shapes = @($shapes) } |
  ConvertTo-Json -Depth 6 | Set-Content (Join-Path $env:TEMP 'cad-1000.json')
```

- 2 点が一致する線分が含まれる場合は、読み込みで拒否される。実行して拒否された場合は、生成の種を変える。
