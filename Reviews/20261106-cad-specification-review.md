## 指摘の詳細

### 1. 保存確認のボタンが、OS 標準のメッセージボックスでは実現できない（中）

- 場所：4.6（167行）、4.0（73行）、A-16（451行）。設計書 `Documents/20261105-cad-architecture.md` 395行も同じ前提です。
- 根拠：4.6 は保存確認のボタンを「Save / Don't Save / Cancel」と定めています。一方、4.0 と A-16 は「エラー表示のメッセージボックスは OS 標準」「Material Design 固有のダイアログは使わない」とし、設計書は `AskSaveChanges` を `MessageBox` で実装するとしています。WPF の `MessageBox` はボタンの文言を変えられず、選べるのは Yes / No / Cancel だけです。
- 影響：実装時に仕様（ボタンの文言）と設計（`MessageBox`）のどちらかを破ることになり、テスト計画書 T-VM-02、M-18 の期待結果と一致しません。
- 改善案：次のどちらかに決めてください。(a) 文言を `Save changes to "<name>"?` のまま、ボタンを Yes（保存）／No（保存しない）／Cancel とする。(b) ボタンの文言を変えられる OS 標準の Task Dialog を使うと明記する（設計書の `DialogService` と依存パッケージも見直しが必要）。変更の小さい (a) を推奨します。

### 2. 画像（EMF）出力の大きさに上限がない（中）

- 場所：5.7（259–260行）、A-10（445行）、5.3（219行）、7章。
- 根拠：画像は「1 論理単位 = 1 ピクセル」、範囲は「対象図形の外接矩形」です。一方、図形を論理領域の外へ移動することは禁止されておらず（219行）、座標の制約は有限であることだけです（331行）。図形を 100,000 論理単位離して置くと、ドキュメント全体の画像は約 100,000 × 数百 px 以上になり、ドキュメント全体が対角に広がると数十億ピクセルになります。7章には、出力の生成に失敗した場合の振る舞いもありません（「クリップボード書き込み失敗」だけです）。
- 影響：メモリー不足によるアプリケーションの停止・応答停止、または例外が握りつぶされる実装になりえます。受け入れ条件で確認されません。
- 改善案：出力の最大ピクセル数（例：一辺 10,000 px、または総ピクセル数）を仮定として置き、超える場合は「縮小して出力する」か「エラーを表示してクリップボードを変更しない」かを定めてください。7章に行を追加し、AC を 1 件追加してください。

### 3. 属性ウィンドウがアクティブなときのショートカットと `Alt+F4` が未定義・矛盾（中）

- 場所：4.2（105、112行）、4.5（136行）、5.4（228行）。
- 根拠：
  - 4.2 は `Alt+F4` を Exit（保存確認後に終了）としています。一方、4.5 は属性ウィンドウの閉じるボタンを非表示にして「破棄しない」としますが、属性ウィンドウがアクティブなときに `Alt+F4` を押すと、OS の既定では属性ウィンドウ自体が閉じます。アプリの終了、属性ウィンドウの非表示、何もしない、のどれになるかが決まっていません。
  - 属性ウィンドウにフォーカスがあるとき（テキストボックス以外。スライダーやコンボボックスなど）の `Ctrl+Z` / `Ctrl+Y` / `Delete` / `F4` / `Ctrl+S` が、メインウィンドウのコマンドとして働くかどうかが未定義です。5.4（228行）はテキスト入力部品にフォーカスがある場合だけを定めています。WPF ではメインウィンドウの `InputBindings` は別ウィンドウのキー入力を受け取らないため、決めておかないと「`F4` で開いたウィンドウを `F4` で閉じられない」といった動作になります。
- 影響：AC-10（表示／非表示）、AC-20（Exit の保存確認）の判定が、どちらのウィンドウがアクティブかで変わります。
- 改善案：「属性ウィンドウがアクティブなとき、`Alt+F4` は属性ウィンドウを非表示にする（`F4` と同じ）」「`F4`、`Ctrl+Z`、`Ctrl+Y`、`Ctrl+S` などのメインウィンドウのショートカットは、テキスト入力部品にフォーカスがある場合を除き、属性ウィンドウからも働く（または働かない）」と定めてください。

### 4. クリック判定の優先順位が未定義（低）

- 場所：5.3（203、216行）、A-9（444行）。
- 根拠：判定の許容範囲は、ハンドル約 6 px、線上約 5 px です。選択中の図形のハンドル、選択中の図形の線、その上に重なる別の図形の線が、同じクリック位置で同時に該当しうるのに、優先順位は「重なる場合は最も上の図形」（203行）しかありません。
- 影響：下にある選択中の図形のハンドルを、上の図形と重なる位置でドラッグできるかどうかが、実装者によって分かれます。
- 改善案：「選択中の図形のハンドル → 図形の線（上にある図形から順）」のように、判定の順序を明記してください。

### 5. ドラッグ中にマウスキャプチャを失った場合の扱いが未定義（低）

- 場所：5.3（217行）、5.10（285行）。
- 根拠：ドラッグの確定は「マウスを離した時点」、取り消しは `Esc` と定めています。しかし、ウィンドウの外でボタンを離した場合、`Alt+Tab` や他のウィンドウの表示でキャプチャを失った場合が定義されていません。
- 影響：ドラッグ中の状態が残り続ける（5.10 の各コマンドが無効のまま）か、途中の位置が Undo 履歴に入らないまま反映されるおそれがあります。AC-08、AC-26 の境界条件です。
- 改善案：「ウィンドウ外で離した場合は確定する」「キャプチャを失った場合は取り消す（`Esc` と同じ）」など、1 行で定めてください。

### 6. 全体図が広がったときの拡大の上限の補正が未定義（低）

- 場所：5.6（242、244行）、A-7（442行）。
- 根拠：拡大中に全体図が変わると「縮尺を維持」し、下限側（全体図の縮尺を下回る場合）の補正だけを定めています。全体図が広がると全体図の縮尺は小さくなるため、維持した縮尺が「全体図の 32 倍」を超えることがありえますが、上限側の補正がありません。
- 影響：上限を超えた拡大率が表示される、またはその状態からさらに拡大できるかが決まりません。AC-30 の判定にも関わります。
- 改善案：「上限を超える場合は上限に合わせる」か「全体図の変化による一時的な超過は許し、ホイールでの拡大だけを止める」かを明記してください。

### 7. 「点が一致する」の判定が未定義（低）

- 場所：5.2（195行）、6.3（323–329行）。
- 根拠：6.3 の制約は「一致しない」「半径 > 0」「幅と高さが 0 より大きい」と定めますが、実数の比較を完全一致で行うのか、許容誤差を持つのかが書かれていません。画面からの入力では、同じピクセルのクリックは同じ論理座標になりますが、拡大中は 1e-6 程度だけ離れた点も入力できます。
- 影響：ほぼ同じ位置の 2 点を持つ曲線は、スプラインの計算で極端な形状になりえます。読み込み時の検証（7章）と入力・編集時の判定で、実装が食い違うおそれがあります。
- 改善案：「完全一致で判定する（ほぼ同じ点は許す）」か「論理単位で一定の許容誤差内を一致とみなす」かを決め、入力・編集・読み込みで同じ判定を使うと明記してください。

### 8. 独自形式に含まれる図形の数が未定義（低）

- 場所：6.6（357行）、7章の「不正とみなす条件」（376–383行）。
- 根拠：Copy は選択中の 1 図形だけを出力しますが、Paste で受け取るデータの図形の数（0 個、2 個以上）の扱いがありません。複数の図形を貼り付けた場合、5.10（287行）の「貼り付けた図形を選択する」は、複数選択を対象外とする 1.2 と矛盾します。
- 改善案：「独自形式の図形はちょうど 1 個。それ以外は不正」とするか、「複数の場合は全部を追加し、最後の図形を選択する」などを定めてください。

### 9. 設定とドキュメントのバージョン・値の検証が未定義（低）

- 場所：6.5（350行）、7章（373、385行）。
- 根拠：
  - 設定ファイルは形式のバージョンを持ちますが、現行より新しいバージョンの扱いがありません。「不正・破損」として退避されると、新しい版のアプリケーションの設定が、古い版の終了時の保存で失われます。
  - 設定の既定属性が範囲外（太さ 1000 など）、ウィンドウのサイズが負、といった値の不正を「不正・破損」に含むかどうかが不明です。
  - ドキュメントについては「現行より新しいバージョン」だけを専用に拒否しており、0 や負のバージョン番号の扱いが「不正とみなす条件」に含まれていません。
- 改善案：設定にも「不正とみなす条件」を設けてください（項目ごとに既定値で補うか、全体を不正とするか）。ドキュメントの不正条件に「バージョンが 1 未満」を加えてください。

### 10. 入力中・ドラッグ中の Copy as Metafile / Copy as Image の可否が未定義（低）

- 場所：5.10（284–285行）、4.2（110–111行）。
- 根拠：5.10 は、入力中・ドラッグ中の Undo / Redo、Paste、Copy、Delete を定めていますが、Copy as Metafile と Copy as Image は挙げていません。入力中は選択がないため、これらはドキュメント全体を出力できることになります（入力中の図形は含まない、という 259行の規定と組み合わせると実行は可能）。
- 改善案：可否を明記してください（入力中は実行可、ドラッグ中は不可、など）。

### 11. 描画領域の背景と、論理領域の「白い背景」の区別が不明確（低）

- 場所：4.0（69行）、4.3（120行）。
- 根拠：4.0 は「描画領域の背景は白」、4.3 は「論理領域の外形を、薄い枠線と白い背景で示す」としています。描画領域全体が白なら、論理領域の白い背景は区別できず、論理領域の外側の色が定まりません。
- 改善案：「描画領域全体が白で、論理領域は枠線だけで示す」のように、どちらか一方の表現に揃えてください。

### 12. 承認で確定した未決事項が「レビューで確認」のまま残っている（低）

- 場所：9.2（464–468行）、10章（472–477行）。

- 影響：仕様書だけを読むと、U-2、U-5 が未確定に見えます。状態行（承認済み）とも合いません。
- 改善案：9.2 の「扱い」列を確定内容（例：「仕様書の承認により A-17 で確定」）に更新し、改訂履歴に承認日を追加してください。内容を変えない記録の更新ですが、本書の変更にあたるため、承認状態の扱いはユーザーの判断に従ってください。
