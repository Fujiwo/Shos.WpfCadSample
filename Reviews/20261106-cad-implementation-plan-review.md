### 2. ビルド・テストのコマンドがリポジトリ指示と食い違う（中）

- 場所：3.2 の C-1・C-2（80–81行）、I-10 の完了条件（232–233行）。
- 根拠：リポジトリ指示（`.github/copilot-instructions.md` 59–61行、2026-11-06 改訂）は、コマンドを `/` 区切り（`dotnet build Source/Shos.WpfCadSample/Shos.WpfCadSample.slnx`）で書き、Windows の `dotnet`（WSL からは `dotnet.exe`）で実行するとしています。本書はバックスラッシュ区切りで、実行環境の指定もありません。bash ではバックスラッシュがエスケープとして解釈され、パスが壊れます。WPF のプロジェクトは Linux の `dotnet` ではビルドもテストもできません。
- 影響：段階の完了条件 C-1・C-2 を、エージェントの実行環境によっては確認できません。
- 改善案：コマンドを `/` 区切りに改め、「Windows の `dotnet` で実行する（WSL からは `dotnet.exe`）。実行できない場合は、確認できなかったことを進捗記録に書く」と明記してください。1.3 の開発環境の記述（SDK のバージョン）も、Windows 側の SDK であることを明記してください。
